左邊是所有人都經歷過的「真正最終版」地獄。右邊是同一份檔案在 GitHub 上：一條時間軸，每一格是一次存檔加一句說明，任何一格都能點回去看當時的完整內容。這就是 GitHub 對非工程師最大的價值。
A GitHub

你會看到的畫面

  github.com/<帳號>/<repo>/commits（換成你的真實截圖）
Public＝公開；私人會寫 Private
每一格＝一次存檔＋一句「改了什麼」
綠勾＝自動檢查通過，紅叉＝有一項沒過
這是反向搜尋策略產生器（公開倉庫）的修改紀錄頁真實畫面。每一格是一次存檔加一句說明：fix 開頭是修錯、refactor 是整理。右邊 5/5 綠勾代表五項自動檢查全過，4/5 紅叉代表有一項沒過，那次是還沒把建置工具裝進正式環境。看懂這一頁，就看得懂九成的 GitHub 頁面。
A GitHub

第一次用：三步，不必打指令

  1. 註冊帳號，按右上角「＋」→ New repository取一個英文名字，選 Private（私人）
  2. 按「Add file」→ Upload files，把檔案拖進去Word、PDF、HTML 都可以，不限程式碼
  3. 下面那格寫一句「這次改了什麼」，按 Commit這句話就是修改紀錄；寫給三個月後的自己看
完全在網頁上操作。等你熟了再學終端機指令；不熟的時候，網頁拖拉一樣是正規用法。
三步全部在瀏覽器完成。很多教學一開始就教指令，把人嚇跑。先用網頁建立「存檔加留言」的習慣，指令是之後的事。想學指令的人：git add -A、git commit -m "訊息"、git push，就是這三步的鍵盤版。

什麼是「靜態網頁」？打開就是固定內容的頁面：教案、講義、工具說明。不需要登入、不需要每次現算的，都算。
靜態網頁就是「檔案本身就是網頁」，例如這份 HTML 簡報。需要登入、需要 AI 計算的工具不是靜態，那些去 Zeabur。分清這一點，就知道東西該放哪。
